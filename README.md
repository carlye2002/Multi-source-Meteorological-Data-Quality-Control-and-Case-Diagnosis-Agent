# Multi-source-Meteorological-Data-Quality-Control-and-Case-Diagnosis-Agent
构建一个面向强天气个例分析的多 Agent 系统，自动完成从资料接入、质量控制、诊断计算、图表生成到报告初稿输出的全过程。
一、核心痛点：
气象研究中，站点、雷达、卫星、再分析资料来源多、格式杂，人工质控和个例诊断非常耗时，尤其是在强降水、台风、极端高温等事件复盘中，需要反复查资料、画图、比对预报误差。
二、解决方案

构建一个面向强天气个例分析的多 Agent 系统，自动完成从资料接入、质量控制、诊断计算、图表生成到报告初稿输出的全过程。

该系统主要解决气象研究中的几个痛点：

资料来源复杂
站点观测、雷达、卫星、ERA5、WRF、GFS、ECMWF 等资料格式不同，时间分辨率和空间分辨率不一致，人工整理成本高。
质控流程重复
强天气复盘前，研究者通常需要反复检查缺测、异常值、站点跳变、雷达拼图缺口、模式场时间错配等问题。
诊断图表生成耗时
每个个例都需要绘制降水、风场、水汽通量、涡度、散度、垂直速度、CAPE、K 指数、低空急流等图表，代码重复度高。
个例报告起草慢
研究人员需要手动解释天气背景、触发机制、模式偏差和观测特征，前期文字整理耗时较长。
三、Agent 模块设计
1. 数据接入 Agent

负责读取和识别不同气象资料。

主要功能：

自动识别 NetCDF、GRIB、CSV、TXT、GeoTIFF 等格式；
解析变量名、单位、时间范围、空间范围；
统一时间坐标、空间坐标和变量命名；
判断资料是否满足当前个例分析需求。

示例任务：

输入一个台风暴雨个例的时间范围和资料路径，系统自动识别可用的站点降水、雷达回波、ERA5 再分析和 WRF 输出文件。

2. 质量控制 Agent

负责对观测资料和模式资料进行自动质控。

主要功能：

检查缺测值；
检查极端异常值；
检查时间序列突变；
检查站点空间一致性；
检查模式输出变量是否完整；
生成质控日志。

示例逻辑：

如果某站 1 小时降水明显超过周边站点，系统不会直接删除，而是标记为“疑似异常”，并结合雷达回波和邻近站点给出判断依据。

3. 诊断分析 Agent

负责根据天气类型选择诊断方案。

主要功能：

自动判断个例类型，例如强降水、台风、暴雪、高温、寒潮、对流大风；
选择对应的诊断变量；
自动生成诊断图；
对关键天气系统进行文字解释。

例如强降水个例会重点分析：

850 hPa 水汽通量；
850 hPa 风场；
500 hPa 环流形势；
700 hPa 垂直速度；
地面辐合线；
CAPE / CIN；
雷达回波演变；
累计降水分布。
4. 绘图与代码 Agent

负责自动生成并运行 Python 绘图代码。

主要功能：

生成 xarray、MetPy、Cartopy、matplotlib 代码；
自动选择地图范围、色标、等值线间隔；
生成标准化图表；
如果代码报错，自动修复；
输出图表和代码日志。
5. 报告生成 Agent

负责将诊断结果转化为个例分析报告。

报告结构固定为：

个例概况；
实况特征；
环流背景；
水汽条件；
动力抬升条件；
不稳定能量条件；
雷达和卫星演变；
模式预报偏差；
结论与后续问题。
四、核心逻辑流

用户输入研究目标
↓
数据接入 Agent 读取多源气象资料
↓
资料解析与标准化
↓
质量控制 Agent 检查缺测、异常值、时间错配和空间异常
↓
诊断分析 Agent 判断天气类型并选择分析方案
↓
绘图与代码 Agent 自动生成诊断图表
↓
结果校验 Agent 检查图表、单位、变量和时间范围是否正确
↓
报告生成 Agent 生成个例分析初稿
↓
人工审核、修改和确认
↓
沉淀为个例库和可复用诊断模板
